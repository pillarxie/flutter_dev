# 会话日志输出与清空

日期 2026-11-05

## 功能范围

- 日志工具栏提供「清空当前会话日志」。当前会话已有输出时，即使搜索或错误筛选使面板为空，也可以清空该会话的已缓存记录。运行中的会话继续接收后续输出，已结束且仍保留的会话也可以清空。
- 清空在 Rust 缓冲区生效。刷新、切换搜索和错误筛选、离开并返回日志页时，都从当前会话清空后的缓冲区读取。各会话日志独立，构建、测试和 DevTools 使用各自的输出路径。
- 优化输出的可读性和跟随体验。DAP 输出尾部的行终止符仅结束上一行，保留正文中的空行及堆栈。恢复跟随时立即定位到当前最新输出，搜索无结果与会话暂无输出显示不同空态。

## 现有链路

- `rust/src/session.rs` 将 DAP 输出、启动进度和工具错误写入 `Session.logs`。部分 iOS 会话的应用 stdout / stderr 由 `rust/src/vm_logs.rs` 按行收集并写入同一缓冲区。`rust/src/log.rs` 保留单会话最近 10000 行或 4 MiB，日志 ID 单调增加。
- `rust/src/api/core.rs` 每 150 ms 检查最新日志 ID，用 `OutputAvailable` 通知 Flutter 按游标取页。日志面板每页最多 200 行，显示最近 1000 行或 512 Ki 字符。
- 当前查询及刷新从头回放保留记录。清空只作用于 Flutter 列表会在重新读取后失效。读页和清空的返回也可能跨过切换会话或切换筛选条件的时点。

## 实现步骤

1. 在 `rust/src/log.rs` 的缓冲区同一锁内清除条目、字节计数与轮转提示，记录清空时的最后一个 ID，并保留 ID 生成器的进度。读页携带清空水位，让客户端可以在通知延迟或重新挂载后与 Rust 同步。
2. 在 `rust/src/api/core.rs` 通过会话 ID 清空对应缓冲区，释放日志锁后发送 `OutputAvailable`。用仓库规定的 flutter_rust_bridge 2.12.0 生成两端绑定，通过 `workbench_models.dart` 与 `workbench_bridge.dart` 暴露清空和读页元数据。
3. 在 `lib/features/logs/log_panel.dart` 添加工具栏操作和失败反馈。发起清空的面板在成功后重置投影和游标，从核心重新加载。其他面板处理新分页时移除清空水位及之前的条目。清空失败时保留记录，清空期间禁用重复操作。会话变更沿用 ID 和 generation 隔离，筛选和清空后的重读沿用读页 revision。
4. 在 DAP 输出入口消费尾部的单个换行符，保留中间换行和空行，并使已分行的 VM 日志仍按原路径写入。调整日志面板恢复跟随的定位和空态，复用现有主题与滚动控制器。

## 验收

- 核心验证清空前后 ID 单调、空页保留清空水位、容量轮转重新计数、清空后新输出可以分页读取。检查换行、连续空行和多行堆栈的行边界。
- 面板验证清空作用于当前会话的全部记录，刷新和筛选无法读回旧输出，进行中的读页或会话切换无法恢复已清空记录，清空期间到达的新输出可以继续显示。覆盖失败、无会话、明暗主题和 560px 窗口。
- 运行 Rust fmt、Clippy、测试、Flutter analyze、Flutter 测试及 `git diff --check`，同步 README 和使用说明，将实际执行结果记入 `docs/validation.md`。

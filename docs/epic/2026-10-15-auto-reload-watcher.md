# 自动热重载监听与可靠性增强

日期：2026-10-15。用户授权修复自动热重载漏触发，改成系统文件监听加轮询兜底，支持本地依赖，完成验证后重新打包 macOS 应用。

## 目标与范围

- 保留按项目持久化开关与已有 Flutter 展示投影。Rust 继续负责监控、变更合并、会话能力判断和 DAP 请求，不启动第二份 `flutter run`。
- 同一规范化项目路径的会话共享一个监控器。项目不同则隔离；共享监控不改变各会话使用的 SDK、状态及 generation。
- 系统文件事件为主要来源，低频有界扫描负责校验和恢复漏事件；系统监听建立失败或运行时出错时仍可轮询工作。普通用户不需要新增监听参数。
- 监听应用 Dart 源码及实际解析到的本地依赖，包括传递 path 依赖、dependency_overrides 和 workspace 本地包。忽略 SDK、远程包缓存、构建输出、版本控制和工具缓存目录。
- 不扩展自动热重启、自动 pub get、资源及原生代码热更新，不改变手动操作语义，不新增公开桥接 API。

## 已确认的问题

当前 `rust/src/auto_reload.rs` 每会话以 350ms 周期遍历项目，按路径、修改时间和大小建立快照；只读项目树且跳过符号链接，无法覆盖目录外本地依赖。发现变更后在 `hot_update(false)` 之前清除待处理标记，若与手动操作争抢锁失败则丢失本次变更；扫描失败还会清空基线。现有 600ms 防抖、模式能力限制、错误日志及终态释放需要保留。

## 实现方案

1. 使用 Rust `notify::RecommendedWatcher` 监听目录；合并创建、写入、删除、重命名及编辑器原子替换保存产生的事件。事件传递必须有界，溢出或无法识别的事件至少标记需要重新扫描，不能静默丢失变化。避免同步回调进行磁盘扫描或阻塞异步执行器。
2. 以 canonical 项目路径共享监控器和变更版本。监听目录去重并去除嵌套重复根；监听范围与扫描忽略规则一致。不无界跟随目录内符号链接，本地依赖根可以在规范化后显式监听。
3. 读取 `.dart_tool/package_config.json` 的实际解析图，并结合 pubspec 本地路径配置区分本地包与 SDK、包缓存。支持相对 URI、绝对 file URI、空格及非 ASCII 路径；配置变动重新发现根，替换监听时保留待处理变更。配置暂时缺失或写入未完成时保留上次可用根并继续监控项目本身，不误删已有依赖监听。扫描和解析保留明确容量限制及可诊断日志。
4. 正常监听时以约 5–10 秒周期校验文件快照，监听故障时可缩短到约 2 秒。轮询比较路径、时间和大小覆盖增删改，首次建立基线不触发重载；读取暂时失败不能清除已知变化或把下一次成功扫描当作全新无变化基线。恢复监听及轮询使用去重、防抖，单次保存不会因两个来源重复重载。
5. 用单调变更版本和每会话已处理版本管理请求。会话忙或未获得操作锁时不消费版本；确定进入一次 DAP 热重载后才处理该版本。重载期间保存的更新版本必须保留，在本次完成后防抖补执行。实际编译错误记录并消费本次尝试版本，等待后续源码变化，避免同版本无限重试刷日志。
6. 继续遵循 Debug、显式 hotReload 能力及 noDebug 约束。关闭开关后不执行积压任务，重新开启建立新基线；停止、失败及结束后释放该会话订阅，最后一个有效订阅离开后释放项目监控。页面离开不影响后台监控。日志对重复监听或扫描故障去重，恢复后可再次报告新的故障。

## 关键文件与顺序

- `rust/src/auto_reload.rs`：共享监控、目录发现、事件合并、扫描兜底、防抖及版本状态。
- `rust/src/session.rs`：内部自动热更新入口明确区分忙与实际请求结果；继续复用手动 DAP 路径及互斥保护。
- `rust/src/api/core.rs`：仅在共享监控生命周期需要时调整内部接线；保留设置保存与会话创建的串行保障。
- `rust/Cargo.toml`、`rust/Cargo.lock`：引入系统监听依赖并保留锁文件。
- `rust/examples/sdk_smoke.rs`：扩展可丢弃样例验证；不操作用户业务项目。
- `README.md`、`docs/usage.md`、`docs/development.md`、`docs/compatibility-baseline.md`：同步行为和限制；`docs/validation.md` 记录本次实际执行结果。

## 必须回归的场景

- 首次基线不重载；连续保存合并；同版本的原生事件及轮询结果只重载一次；原子替换、创建、删除、重命名可触发。
- 手动重载抢锁、会话 operation 忙时不丢变更；自动请求进行中再次保存，在完成后补一次；编译失败不会无变化无限重试，新保存可再次执行。
- 两个同项目会话只建一个监控，各自独立处理版本；停掉一个不影响另一个；最后订阅停止释放资源。关闭再开启、配置无关保存、会话切换及迟到事件不误触发。
- 目录外 path 包、传递 path、覆盖依赖和 workspace 包修改能触发；包缓存与 SDK 变更不会触发；根规范化去重且没有无界符号链接遍历。
- 依赖配置更新可加入或移除根；暂时缺失或损坏保留可用监控；系统监听失败、事件溢出或漏事件由轮询恢复；扫描短暂失败不丢已有版本及基线。
- 保留 Debug / Profile / Release、noDebug 与显式能力限制，停止及失败不再请求 DAP。
- 运行 Rust fmt、严格 Clippy、完整 Rust 测试；检查 Flutter analyze 与相关回归；`git diff --check`。使用拥有所有权标记的可丢弃真实 Flutter 样例执行应用保存、本地依赖保存、禁用和停止链路；无法实际执行的项目明确记录。
- 构建 macOS Release，确认应用产物和签名校验；构建结果不等于 Windows / Linux 实机通过，不替换或启动用户当前应用，不混入既有无关脏改动。
